# PR-V2-17.4 — Deterministic Browser E2E Server Lifecycle

## Problem

The PR17.2/17.3 browser command seeded `.e2e-state.json` and then could remain silent while Playwright waited for its `webServer` lifecycle to become ready.

## Change

Playwright no longer owns the Next.js server lifecycle. `scripts/e2e/run-browser.mjs` now:

1. starts `pnpm start -p 3100` explicitly;
2. streams Next.js stdout/stderr with an `[next]` prefix;
3. polls the configured URL until it returns an HTTP response;
4. fails after 60 seconds with the last readiness error;
5. launches Playwright only after the server is ready;
6. always terminates the server when Playwright exits or the runner receives SIGINT/SIGTERM.

The browser suite uses `E2E_BASE_URL=http://127.0.0.1:3100`, avoiding collisions with a manually running Auno server on port 3000.

## Verification required locally

```bash
pnpm e2e:browser
```

Expected lifecycle:

```text
[E2E] Starting Next.js on http://127.0.0.1:3100...
[next] ...
[E2E] Server ready: http://127.0.0.1:3100
[E2E] Starting Playwright...
...
3 passed
```

A server startup failure should now be visible within 60 seconds rather than appearing as an indefinite silent wait.

## Status

Browser E2E remains **unverified until the command executes successfully on the local Auno environment**.
