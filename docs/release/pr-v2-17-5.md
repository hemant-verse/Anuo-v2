# PR-V2-17.5 — Browser E2E Rate-Limit and Selector Stabilization

## Problem

The browser release gate exposed two test failures that were not core domain failures:

1. The buyer journey used a placeholder-only search locator while the responsive feed intentionally renders two search inputs, causing Playwright strict-mode failure.
2. The seller login journey hit the global API middleware burst limiter during normal page initialization/login traffic. The login endpoint already has its own IP+account sliding-window policy.

## Fixes

- Target the desktop marketplace search by its unique accessible role/name: `searchbox` / `Search marketplace`.
- Raise the generic API burst ceiling from 10 to 60 requests per 10 seconds per IP. Sensitive endpoints retain their endpoint-specific limits in `lib/rate-limit.js`.
- No authentication, authorization, or domain rule was weakened.

## Verification target

- Buyer browser journey: pass.
- Seller/admin browser journey: pass.
- Security redirect journey: pass.
- Unit/integration/build/lint gates remain unchanged.
