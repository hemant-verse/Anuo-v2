# PR-V2-07 — Marketplace UI Feature Boundary

## Goal

Move marketplace product/favorite/category fetching behind feature modules and establish a reusable ProductCard so pages do not own API contracts or duplicate listing markup.

## Changes

- `features/products/api.js` owns canonical product read/write calls.
- `features/favorites/api.js` owns favorite operations.
- `features/categories/api.js` owns category retrieval.
- `components/product/ProductCard.jsx` owns reusable listing presentation and favorite interaction.
- Feed uses canonical product/favorite/category feature APIs.
- Favorites uses the shared ProductCard.
- My Listings uses the product feature API.
- Product detail uses the product feature API.
- Home live ticker uses the product feature API.
- Category endpoint now uses the canonical `{ success, data, error }` response contract.

## Behavior fixes

- Feed pagination now trusts `pagination.hasNextPage` instead of deriving a page count from item count.
- Favorite toggling is explicit add/remove rather than depending on an implicit toggle endpoint.
- Favorite and product rendering no longer duplicate the same card markup.
- Product API URLs are no longer scattered across marketplace presentation components.

## Deliberate remaining boundary

The sell page still uses `/api/products/sell` because it performs multipart image upload and requires the upload adapter. That migration belongs to the next product-creation step rather than pretending multipart upload is equivalent to the JSON create contract.

Admin moderation also remains on its temporary adapter until the AdminService/moderation API migration.
