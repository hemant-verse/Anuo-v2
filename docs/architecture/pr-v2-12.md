# PR-V2-12 — Security and Production Hardening

## Scope

This pass hardens the V2 architecture after legacy removal. It does not introduce a new domain; it closes security and concurrency gaps that are easy to miss in feature-level implementation.

## Authentication hardening

- Login, registration, OTP send/verify, password reset, and refresh are rate limited through Upstash.
- Rate-limit identifiers combine request address with a hashed account identity where applicable.
- OTP failed-attempt increments are atomic.
- OTP consumption is atomic, preventing the same valid code from being consumed twice concurrently.
- Refresh-token rotation is atomic; two concurrent uses of the same current refresh token cannot both rotate successfully.
- Reuse of a previous refresh token revokes the session.
- Production refresh cookies use the `__Host-` prefix, `HttpOnly`, `Secure`, `SameSite=Strict`, and `Path=/`.
- Password reset continues to revoke all active sessions.

## Domain concurrency hardening

- Product availability transitions use compare-and-set semantics so concurrent state changes cannot both succeed from the same prior state.
- Admin moderation decisions use compare-and-set semantics so concurrent decisions cannot both mutate the same pending product.

## HTTP hardening

The Next.js application now sends baseline browser security headers:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy` disabling camera, microphone, and geolocation
- `Cross-Origin-Opener-Policy: same-origin`
- `X-Powered-By` is disabled

A strict CSP is intentionally not added here because the final policy must be derived from the production asset/font/image strategy rather than deployed speculatively.
