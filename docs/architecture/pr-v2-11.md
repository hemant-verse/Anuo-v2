# PR-V2-11 — Legacy Removal

## Scope

Remove the V1 Product compatibility surface after repository migration verification established that active application callers use the canonical V2 APIs and models.

## Removed

- `/api/products/create`
- `/api/products/sell`
- `/api/products/feed`
- `/api/products/my-listings`
- `/api/products/product/:id`
- `/api/products/pending`
- `/api/products/verify`
- `/api/products/:productId/favorite`
- `/api/user/favorites`
- `models/product.model.js`
- legacy `productStatusSchema`
- legacy `productVerifySchema`

## Canonical replacements

| Removed surface | Canonical replacement |
| --- | --- |
| Product create/sell | `POST /api/products` |
| Product feed | `GET /api/products` |
| Product detail | `GET /api/products/:id` |
| My listings | `GET/PATCH/DELETE /api/products` + `GET/PATCH/DELETE /api/products/:id` |
| Pending products | `GET /api/admin/products/pending` |
| Product moderation | `POST /api/admin/products/:id/approve` / `reject` |
| Favorite toggle | `POST/DELETE /api/favorites/:productId` |
| Favorite list | `GET /api/favorites` |
| Product model | `models/Product.js` |

## Safety gate

The migration verifier now requires the removed routes/model to be absent and scans all remaining application source for legacy imports, legacy API callers, and legacy Product/User field names.

This is a repository-level deletion gate. Production rollout still requires the deployment smoke test and rollback procedure described by the V2 migration strategy before production traffic is considered complete.

## Verification

- `pnpm verify:v2` — must pass
- `pnpm test` — must pass
- Full Next.js build/lint remains a release-environment check when dependencies are installed.
